# TECH DEBT

Осознанные долги с плановым milestone-закрытием. Формат: ID / что / почему сейчас ок / когда закрыть.

## TD-001 — /health: db как tcp-check
- **Что:** проверка БД — TCP-коннект к host:port из `DATABASE_URL`, без реального запроса.
- **Почему ок:** pg-клиент появится только в M2 (Prisma); tcp-check ловит главный случай «упал сервер».
- **Когда закрыть:** M2 — заменить на `SELECT 1` через Prisma (утверждено владельцем, правка №7 от 2026-08-29).

## TD-002 — дублирование buildServer/health в apps/api и apps/bot
- **Что:** идентичный код health-роута и error-обработчика в двух приложениях.
- **Почему ок:** Э5 фиксирует scope `packages/shared` как «zod-схемы, типы, таксономия» — серверный билдер туда не кладём; дублирование ~50 строк до первой расходимости.
- **Когда закрыть:** при первом реальном расхождении bot/api (M5+), вынести в `packages/*` по согласованию с владельцем.

## TD-003 — apps/web содержит только заглушку
- **Что:** корневая страница-плейсхолдер; `/m/[slug]` и `/admin` ещё не существуют.
- **Почему ок:** bridge — M3, admin — M8.
- **Когда закрыть:** M3 (bridge `/m/:slug`), M8 (admin).

## TD-004 — compose-файлы не прогнаны локально в песочнице разработки
- **Что:** среда разработки без docker; валидация `docker compose config -q` выполняется в CI.
- **Почему ок:** GitHub-раннер с docker выполняет шаг в каждом пайплайне; YAML дополнительно проверен парсером.
- **Когда закрыть:** первая выкладка на VPS (M10) — `docker compose -f infra/compose.base.yml up -d` на реальном хосте.
